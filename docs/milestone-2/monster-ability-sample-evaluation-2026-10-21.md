# 六项怪物能力样本与 Luna 消费测试

日期：2026-10-21。状态：有限候选试验完成，技术建议待讨论；不构成规则内容批准或 M2 Exit Gate 通过。

## 结论与可信边界

六项能力已生成，附来源证据、结构化伴随草案、人类阅读卡和用途／依赖说明。10 次独立冷启动 Luna 调用产生 378 条回答，涉及 42 个不同题目；不是 378 个独立规则样本。

本批支持继续研究“专属能力拥有自身事实，共享规则独立维护，调用与例外显式连接”的方向。证据最明确的价值是：能把事实归属、调用修改、状态来源和缺失输入展示为可核查对象。尚不能证明结构化材料比预选原文在规则正确率上更好，更不能据此估计全书准确率、全书工期或线上性能。

在本批限定任务中，建议以 **gpt-6-luna medium 为默认试验档位**，high 保留作复杂／争议案例的对照。首轮主要失败来自输出字段把“未知”写为 false；澄清合同后的 medium 两次均为 42/42，high 一次为 42/42。没有足够证据支持默认升级 high，也没有证明两档等效。暂不提出档位自动路由或执行机制实施。

## 来源与生成验证

依据[有限试验约定](monster-ability-sample-pilot-2026-10-21.md)与当前 M2 合同，本批由 Codex 按用户直接授权制作，并由同一主 agent 对照来源复核。制作与语义复核不是独立人工内容验收；Luna 测试也不能替代规则批准。

证据锁定 M1 Note、Publisher Manifest、原始 HTML Entry、Inventory 和 Artifact／CHM 摘要，同时锁定当前规范、核心 Schema 与工具。28 个原文片段保留精确 Note UTF-8 范围，并核对其在各自原始 HTML 可见文本中的存在；该比较显式移除 Markdown 装饰与空白，不能称为 HTML 与 Markdown 字节相同。来源身份仍未升级。

[来源与故障审计](../../build/m2-monster-ability-pilot-2026-10-21/audit/source-and-fault-audit.json)记录：28/28 来源链检查、六组来源数值核查、13/13 故障注入被拒绝且未写规范输出；不同 Python 进程／哈希种子生成的48个文件字节相同。故障包括错误DC／时长／共享次数、删除父能力或法术、缺卡、多余文件、重复ID、未知引用和输入摘要不匹配。大部分输出故障由重渲染全等捕获，不能据此声称验证器理解了所有规则语义。

[最终完整性回执](../../build/m2-monster-ability-pilot-2026-10-21/final-integrity.json)确认输入与工具锁、47个交付载荷文件、两轮冻结题库／金标准及10份首次答卷保持一致。第48个文件是交付 Manifest。

## 测试设置

遵循用户给定[参考会话](https://chatgpt.com/s/cx_6ad8190ce0fc81918d2d38a672eded18)中的原文、覆盖、正反例与首次答卷保留原则。模型配置参考 [GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna)，评测设计参考 [Evaluation best practices](https://developers.openai.com/api/docs/guides/evaluation-best-practices)。

调用均请求 `gpt-6-luna`，明确 medium／high，`fork_turns=none`，只给冻结材料、题目和输出要求，不发金标准。题库和金标准先于该轮调用冻结。子 agent 遵守读取白名单，这是指令隔离，不是文件系统安全隔离；配置回执也不是独立的后端模型认证。

首轮36题，六项各六题：3次结构化 medium、2次结构化 high、2次原文 medium，共252条。结构化材料41,192字节，原文材料20,308字节；两者均有同批完整相关原文与试验政策，前者额外包含阅读卡和结构化草案。因此对照不能把卡片、JSON和上下文长度的影响分别归因，也没有测试真实全书检索。

有些早期调用合并读取材料，工具输出存在截断风险；至少一份 high 答卷在补读分块后提交。读取方式未完全标准化，因此这是一轮探索性消费试验，不是严格控制的模型排行榜实验。

## 首轮结果：保留失败，不追改答卷

[首轮自动评分](../../build/m2-monster-ability-pilot-2026-10-21/evaluation/automatic-scores.json)；[首次答卷](../../build/m2-monster-ability-pilot-2026-10-21/evaluation/first-submissions)。result 按 JSON 类型和值严格比较，状态单独评分。

| 材料／档位 | 次数×题数 | result正确 | 状态正确 | 引用ID可解析 |
|---|---:|---:|---:|---:|
| 结构化 medium | 3×36 | 102/108 | 107/108 | 108/108 |
| 结构化 high | 2×36 | 70/72 | 72/72 | 72/72 |
| 原文 medium | 2×36 | 66/72 | 71/72 | 72/72 |

每次31道直接规则题的指定结果字段均正确，即217/217；另外5道为三道缺输入、一道错版、一道缺原文。这35条保留性回答的正文均未编造所缺事实，但14处机器字段把应为 null 的未知填为 false，其中两处状态还标成 answered。它们不能被当作正确机器答卷，也不能简单说成14条实体规则幻觉：题目字段“是否已确认”的措辞与“实际条件是否成立”有歧义，原协议虽要求未知为 null，却没有逐字段消除歧义。

主 agent 阅读全部252条正文，发现原文组另有三处额外解释问题：一处将啃咬伤害例外表述得过宽；两处说“只改持续时间和成分”，遗漏其他明确修改。其指定目标字段仍正确，同一答卷另题也能正确限定啃咬例外；这些局部表述仍保留为问题，不能用字段分数掩盖。

原自动引用评分有34处过严：强制引用题目已给定前提的来源，或强制指定一条政策而不接受同义适用政策。它们不应冒充模型引用错误。原评分完整保留，逐条复核记录在[人工裁决](../../build/m2-monster-ability-pilot-2026-10-21/manual-adjudication.json)。就所问字段而言，所有引用均可定位并提供足够支持；该结论不覆盖上述额外解释中的过度概括。

## 第二轮：只澄清输出合同，样本材料不改

新增[三值输出合同](../../build/m2-monster-ability-pilot-2026-10-21/evaluation-r2/output-contract.md)：true是确认成立，false是确认不成立，null是缺输入无法判断；同时要求 status 与正文一致、例外不扩大范围。明确 `confirmed_damage` 表示实际伤害事实，而不是“能否确认”的回答。引用要求改为最少且充分的依据，不要求把题目给定前提重复证明。

使用36道原题加6道同类新场景：明确未命中、体型未知、121尺超距、魅惑已两小时、共享次数耗尽、只有震慑标签。新场景不是随机保留集，复测也不是独立外部验证。两次 medium、一次 high，共126条。

## 对五项边界的建议

| 合同重点 | 样本支持的下一步边界 | 尚未证明／替代方案取舍 |
|---|---|---|
| 能力归属 | 数值、触发和体型门槛由具体能力拥有；父级约束单独引用 | 全部复制进每张卡容易遗漏更新；仅父级链接又难以独立消费。候选是事实单独维护、消费时组装必要上下文 |
| 法术调用与例外 | 基础法术保留原文；调用处逐项列修改与适用范围 | 全量复制法术便于读却重复维护；只有法术名会漏例外。通用覆盖语言的形式化语义仍待讨论 |
| 来源特定状态 | 定义与当前实例分开；实例关系至少能表达施加者、能力、目标和有效性 | 单个受擒／震慑标签不足；本轮没有实现状态 Runtime，也未覆盖叠加、冲突和重连恢复 |
| 用途覆盖 | 声明支持哪些能力问题、依赖什么、缺什么；无法判定时保留未知 | 六项能力不等于六只完整怪物；随机眼波全集、全部形态、完整施法表和全书召回未测 |
| 包依赖 | 以怪物能力组件引用共享状态／法术组件；构建、来源与消费依赖分别说明 | 本次trial-bundle仅演示组件方向；正式Package拆分仍需授权、版本兼容、访问域与迁移裁决，不应按每个模块直接建包 |

继续采用此方向对未来多系统的意义是：平台保留证据、关系与版本边界，具体怪物／法术术语留在系统扩展。伴随草案不升级为平台核心。正式化后如改变确认边界，仍需 ADR、版本和迁移方案，本轮不实施。
