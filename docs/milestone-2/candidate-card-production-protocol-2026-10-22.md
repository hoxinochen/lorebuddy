# 候选卡生产协议草案

日期：2026-10-22。状态：本批方法整理，待后续验证；不是正式卡标准、Schema或下一批自动启动授权。依据：[七卡优化结果](seven-card-optimization-report-2026-10-22.md)。

## 1. 目的与边界

先形成可供辅助判定使用、能追溯和纠错的候选材料，继续用正例、反例和交叉关系暴露问题。候选协议达到可接受稳定性后，再依据施工协议一次性讨论正式转换。旧8张测试卡、本批7张完整候选卡均不自动成为正式卡。

按事实职责维护、按用途组合、按Package发布仍为方向。卡是阅读视图，不能让它同时拥有所有共享法术和公共状态事实；逻辑模块不等同于发布包。每批先限定规则环境与来源变体，不能按同名、路径或相似正文合并。

## 2. 每张候选卡维护什么

1. 明确来源、语言、规则上下文、候选身份及稳定对象ID；来源出版声明、译文权威、权利分别标记，未核实仍claimed/unknown。
2. 卡头直接列全本卡固有防御与来源依据；AC、印刷HP等静态值与当前实例输入明确区分。未列固有防御不等于运行中不可能获得额外防御。
3. 每项能力保留独立ID、原文证据、激活方式、门槛、目标、效果、次数、结束条件与必要局部例外。不存在的字段不凭同名能力补齐。
4. 原文层与采用层分开。采用纠正须明确绑定对象、字段、依据、裁定状态和未覆盖边界；不能修改原文掩盖差异。
5. 公共法术、状态、动作和数值规则维护在其事实模块；卡引用它们。每个用途把必要正文、局部例外和采用决定同时送达，不能只送一个名称或悬空ID。
6. 人工可读完整候选卡应能找到上述事实及原卡全文；机器表达与阅读视图来自同一候选事实，避免手工维护两份相互漂移的事实源。

本批以JSON和Markdown试验职责，不代表正式Schema已接纳。来源与稳定ID保持是未来可迁移基础；测试文件不要求每次改动留下全量快照，但关键输入、失败、采用及报告不得丢失。

## 3. 五项重点的检查问题

| 重点 | 正确表达 | 必须拒绝的错误表达 |
|---|---|---|
| 能力归属 | 巨魔与断肢再生各自读取；恢复量和抑制按实例 | 同叫再生就共用15，父体火伤抑制传播所有断肢 |
| 法术调用与例外 | 原施法者参数、自身目标、组件例外与专注/结束分别读取 | 组件豁免等于所有法术规则免除；未命中不算攻击检定 |
| 来源特定状态 | 每次施加保留来源主体、效果实例与结束时点 | 同名状态合并成一个计时器，某来源结束就清全部 |
| 用途覆盖 | 伤害题同时提供本卡防御与公共减伤/取整原文 | 只给魔法抗性能力段，遗漏火焰抗性；给公式就认为必能算对 |
| 包依赖 | 概念事实职责与交付用途分开；依赖闭合且访问/权利可满足 | 卡名等于包身份；可读原文等于可公开发布；无限递归装全书 |

跨书同名变体分别维持身份；已选团规则包决定候选来源选择，不能在回答时无依据切换规则版本。

## 4. 生产与测试顺序

当前用户指定的默认消费测试配置为既有事实优先（事实先行）Prompt＋gpt-6-luna high。暂停medium通用Prompt搜索；不默认medium并行对照、全量第二次复核或6.1。此项是测试配置决定，不是准确率保证或新批次生产授权。此前不默认提升档位等表述为该决定之前的试验判断，不再用于覆盖当前配置。


先锁定有限对象、来源和直接用途；整理候选；做装配核查；冻结题目和答案标准；独立首答；核对实际送达；再依据原文评价内容。缺来源或题目有歧义时先登记问题，不用临时改Gold把已见答案变成正确。没有承诺新规则或来源变更时，不让模型输出改写事实。

装配检查至少覆盖：卡头防御不漏、引用可解析、旧ID不变、原文保留、采用值一致、实例与印刷HP不混。用错误样本验证装配失败会阻塞；此检查只证明材料装配，不能替代规则语义或模型正确率验收。

消费题须兼有旧失败和新变式，包含临界数值、缺输入/已知否定、法术结束、跨实例隔离及多来源效果。配对比较保持问题和必要原文相同。结论及解释错误单列为内容失败，首尾矛盾也失败；状态和引用问题单列。平均分不能掩盖系统性漏防御或错误触发。

## 5. 历史试验与残余边界

补充：[Luna high同题单轮](facts-first-high-report-2026-10-22.md)原Prompt27/30、事实先行30/30，为组合方案提供一次积极证据；不改变medium整体未增准的结论；随后用户已指定事实优先＋high为默认，不把单轮全对作为候选内容或正式卡接纳。

后续[同材料Prompt对照](facts-first-prompt-report-2026-10-22.md)已尝试让Luna先列决定性事实再给结论：两方各两轮均57/60，局部改善伴随新错误，未支持全题采用。当时未据此设为默认；后续用户已选择事实先行为默认配置，但它仍不能当可靠性保证。模型消费失败与候选数据缺陷分别登记，不因这些分数自动否定来源正确的候选内容。

本批20/24到21/24，含2处改善、1处新矛盾、2处持续错误。不是“完整候选卡已无大问题”的证据。聚焦材料的批答/单题各6/6也不足以证明稳定性。

因此，卡头整合与来源保持可沿用；长篇阅读步骤仅保留为试验项，逐题调用不设为默认；不新增全量二次问答，不默认升6.1。后续应先决定如何处理可直接核对的数值/防御应用和答案前后矛盾，再限定一次有判别力的验证。确定性核查属于待讨论消费者设计，当前不实施。

是否继续扩大候选，应根据问题性质和用途风险明确判断，不能要求所有LLM答案永远100%才允许生产，也不能把已知重要内容错判包装成单纯展示缺陷。上述历史结果没有自动放行下一批；用户随后明确批准了§7六卡范围，该批完成也不自动授权再扩张。

## 6. 替代方案及影响

保留外部防御补丁改动较少，但完整阅读入口分散；当前采用整合卡头并保留原证据。让卡复制全部共享规则方便单文件阅读，却带来多处维护漂移；采用独立事实模块加可重建用途视图。一次建设通用Schema会过早固定D&D语义；当前只做候选职责试验。每题再问一次或升模可能增加成本，且不是事实生产质量证明；当前保持独立首答及定向实验。

这些选择没有修改已确认平台架构，不新建正式Package。未来转正式节点时仍须履行完整Traceability、授权、确定性编译、Schema及接纳门禁；迁移不复用旧ID表达不同事实，不覆盖Source，也不从本草案推导Terminal写入或公开发布授权。

## 7. 六卡新关系复用结果

[六卡批次](cross-relations-6cards-report-2026-10-22.md)按本协议完成同名异版、整卡替换、延时创建与来源结束关系。新题26/27、旧回归3/3；唯一内容失败为已给定豁免半伤漏用，未发现对应材料缺失，不以失败后重跑覆盖。当前支持按有限范围继续验证候选协议，不表示正式标准成熟或模型稳定全对。

用途闭合必须检查公共规则，而非只检查怪物全文：魅魔上限恢复来自PHB2024长休，未在本能力重复也不等于未知或漏译。整卡替换关系、伴随独立卡和多重攻击组合保持各自事实身份；实验内容双向引用不直接推导正式Package循环依赖。

材料装配可确定性核查，答案语义仍由AI临时审查：原始伤害、豁免后、抗性后的计算阶段不能因模型列过事实就视为正确。显式阶段核对仍为待讨论消费者设计，未实施新检查器；当前继续使用既有事实优先Prompt＋high，未恢复medium调优。全部仍为candidate，下一批对象及用途须另定。
