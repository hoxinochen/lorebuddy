## 3. 数据生产条款

### 3.1 一个事实源，多种派生视图

每个对象维护稳定ID、明确语言/规则环境、候选修订、完整正文及逐能力证据。原文层与结构化抽取/采用层分开。每项能力保留拥有者、激活、资格、目标、条件、效果、次数、时点、结束及例外；来源未写的字段明确记未说明或未知，不从同名条款补齐。

完整性与可执行性分开记录：

| 维度 | 必须说明 |
|---|---|
| 原文覆盖 | 卡/能力/法术/公共单元是否完整，精确范围及保真模式 |
| 结构化覆盖 | 哪些条款已结构化，哪些仍只保留原文，所缺语义是什么 |
| 执行覆盖 | 声明需要哪些表达/能力；消费者当前支持哪些、拒绝哪些 |
| 审核状态 | 来源核查、内容审核和消费验证分别有依据，不能互相升级 |

人类阅读卡、规则簇视图与机器交付由同一候选事实确定性生成。未结构化段落仍完整送达，但不能默认为已执行。当前候选的证据范围记录不冒充已获正式接纳的Source Fragment或Full Fidelity链。

### 3.2 数值与计算式

可参与计算的事实有明确的语义标记、单位、所属条款和来源：伤害固定值、骰式、常数加值、伤害类型、豁免成功/失败分支、抗性/易伤/免疫及关联减损。距离、DC、次数、持续时间和HP门槛分别保持语义，不能都当作伤害输入。

计算式属于版本化的D&D Profile扩展，保留独立表达ID及修订；能力引用表达和自身参数，不复制逐题算式或结果。只允许已登记运算与有限骰式语法，不执行任意代码。新增机制可以完整表达并声明暂不可执行，不强行塞进现有单目标伤害流程。

固定值与实际骰果二选一，骰果由现场输入且不重掷。`damage_taken`、`hp_lost`、最大HP减损及治疗量分别维护；它们不能因为在个别情形相等就共用一个字段。

### 3.3 来源特定效果

规则定义效果的来源、目标、时点和结束条件；现场效果实例另有自身身份及来源实例。相同状态名称可以有多个有效来源，结束一项不能自动删除其他来源。诅咒、点燃、随机状态和最大HP降低即便暂不写入，也必须保留在完整能力及未执行项中。

### 3.4 追溯与来源问题

保留Artifact、Entry、原始路径/编码和摘要证据，结构化字段指向具体证据及采用决定。歧义先记录；需要外部核查时作为独立研究/摄取行为，保存结论和范围，构建不能联网追随最新内容。纠正采用层，保持原文不变。

本合同验收的是内部候选生产及消费契约。正式节点的完整Source Fragment→Entry→Artifact和已审核Mapping→Edition→Work链、Schema及批准门禁仍按AGENTS执行，不由本批测试代替。

## 4. 统一消费与施法契约

### 4.1 请求范围是调用输入

统一字段为`request_scope`，放在调用Envelope/场景测试输入，不放进怪物卡当作规则事实。采用已验证消费者的五项词汇：

| 值 | 本次请求 |
|---|---|
| `damage_and_linked` | 所选单目标的伤害及条文明确关联的减损数值，不应用效果 |
| `full_ability` | 完整能力所要求的全部效果，不能以局部伤害完成代替 |
| `hp_settlement` | HP/临时HP等实例结算 |
| `source_state_change` | 来源效果的施加、终止或撤销 |
| `instance_migration` | 原型替换后的现场HP/资源等数据迁移 |

原24题的范围值从Terminal已公开的`explicit-scope-adapter-2`逐条核对迁入新修订输入；原题与历史文件不覆盖。范围只表达用户问什么，不含正确能力、公式、伤害或防御答案。生产API不依赖题号或测试适配表。按钮可直接指定范围；未来AI也只调用同一契约，缺范围则请求补充，不默认为整项完成。

现场输入还要区分：已提供、未知、明确不适用、已确认不存在。空防御数组不等于防御清单已完整；未给当前HP不等于满血；未给次数不等于可用。原型印刷HP不能覆盖实例当前/最大HP。

### 4.2 法术正文与调用方覆盖

法术拥有完整正文及以下结构化契约，具体字段Schema在本合同获确认后的有限D&D扩展实现中确定，不提升为平台Core：

| 条款 | 法术本体维护 | 调用方维护 |
|---|---|---|
| 身份与参数来源 | 稳定法术ID、语言/规则环境、原文依据、基础环级 | 调用法术ID、施法属性、DC/攻击加值的明确来源或固定覆盖 |
| 激活与目标 | 施法时间、距离、区域、目标类别、可见/自愿等条件 | 明示的目标限定、次数/触发条件及局部覆盖 |
| 成分 | V/S/M、条文明示的消耗/价值及依据 | 免除哪些成分、保留哪些要求；免M不推免V/S或专注 |
| 时长与专注 | 持续时间、是否专注、结束/再次豁免条件 | 仅记录有条文依据的局部覆盖 |
| 资源与环级 | 基础/升环效果与参数 | 实际采用环级、每项/共享次数、恢复依据、参数归属 |
| 结果 | 伤害/状态/其他效果和条件分支 | 调用中特有的效果改变；未覆盖部分继续读取本体 |

未明确事项必须能表达`unknown`或未说明；`false`、不存在与未知不能混用。固定DC14/+6与译注建议DC15/+7分别保留，不以通用公式改写明示采用值。八环调用按实际环级表达，即使当前执行器暂不支持。

明确区分两种承诺：**已确认合法事件的数值结算**与**完整施法合法性判定**。前者可以将经用户确认的资格/豁免等作为现场前提，并在输出列明；后者必须检查自身声明所需全部施法字段。缺完整施法判定能力不能伪装成法术已合法施放，也不阻止已确认事件的受支持数值结算。

### 4.3 输出与能力边界

结果至少区分数据加载/版本错误、引用或绑定错误、缺输入、明确不合法、机制不支持和成功；同时保留请求范围、已完成部分、未执行效果、计算阶段、数值、采用依据及输入身份快照。沿用现有错误词汇时给出明确映射，不随实现改变含义。

程序支持：单事件、单目标、单伤害类型，明确的直接伤害/豁免半伤或零伤、抗性/易伤/免疫、分阶段取整及关联减损数值。不新增HP/临时HP结算、状态应用、多目标完整执行、复杂条件分支或实例迁移。

这些未支持机制照常完整生产；消费者按所求范围停止或返回明确的局部提案。反向索引、预览及可选效果均为派生消费，不改变事实拥有者。候选结果不会自动写Campaign；应用/取消及撤销沿用Terminal自己的已批准边界。

| 来源与字段 | 所有执行参数/调用覆盖有证据及审核依据；未知显式保留；错误数据能阻塞相关执行 |
| 构建与迁移 | 相同输入、工具及审核决定重建字节一致；请求字段迁移无题意变化；旧ID/旧结果可解析 |
| 消费与正确性 | 原24题回归及新24题分别报告；范围内数值/阶段、绑定和边界均符合固定标准；未执行效果准确 |
| 性能与范围 | 原始加载、绑定、核心和总响应时间可复核；首次/预热及复用方式分开；没有硬性微秒承诺或LLM速度倍数 |
| 可审阅收口 | 全部失败、修后结果和Not Run清楚；无未解决、会导致已支持路径返回错误数值或错误归属的阻断项 |

不把平均正确率当作掩盖已知实质错误的门槛。暂不支持且正确说明的机制可以留在批次；缺必要字段却装作成功、跨源误绑、隐去未执行效果不能通过。消费端尚未适配时可完成生产阶段，但P5及整批接纳不能记Passed。

不为低影响文档变更增加形式测试；生产及接口实现采用必要的来源核查、语义正反例、错误注入和受影响回归。已匹配的证据可复用。保留失败和必要输入身份，不要求每次编辑归档全部样本或重复SHA清单。

### 6.4 交付清单

1. 本批对象/来源/全部能力清单与机器可读问题清单。
2. 同源的完整机器语料、完整人类阅读视图、关系及依赖声明。
3. 请求范围与施法契约的有限D&D扩展规范/验证规则，及旧字段迁移与兼容说明；只实现本批会用的结构约束，不实现万能Schema。
4. 原24题迁移回归、新24题、独立Gold，以及不读取答案的运行交接说明。
5. 生产装配/来源/重建报告、错误注入证据、消费方逐题原始结果与评分、性能记录和本批接纳结论。

上述清单按职责组织，不规定每项另起一份Markdown。优先一份规范、一份机器事实、一份派生阅读视图和相应报告，避免同事实多处手工维护。

## 7. 方案取舍、门禁及停止

采用“有限生产契约＋有限计算能力Profile”：既允许完整数据持续生产，又能独立验证已支持任务。继续只做手工参数测试无法约束事实生产和读取；一次冻结全书/所有TRPG的通用Schema会扩大未经验证语义；一次实现全战斗引擎会阻塞反馈，均不采用。

本合同沿用按事实维护、按用途组簇、按Package交付的已确认边界，不更改平台Architecture；目前无需为相同原则重复创建ADR。实施若改变事实归属、稳定身份或正式发布边界，先按AGENTS补ADR/相应规范；不得通过本合同名称绕过。

合同确认、内部候选生产接纳、规则对象正式批准、Terminal消费接纳、Package发布和M2 Exit分别成立。仅在相应来源、Schema、Traceability及批准要求完成后，相关规则对象才能转正式；本批通过不等于全库转正。

实施停止点：完成八对象首批及本会话有权执行的验证，提交本批结论；跨项目消费适配/验收没有收据时保持Pending，不冒充整批通过。未另获授权不改Terminal、不扩全库、不写Campaign、不调用新LLM、不公开Release、不Commit/Push。
