# ADR：在来源转写之外维护明确的中文参考裁定

日期：2026-10-21。状态：用户已确认本轮呈现方向，适用于八卡试点的参考视图；不构成原文官方身份或正式规则批准。

## 决定与理由

目标是形成可用、可理解、可纠错的中文参考材料。来源忠实保留与参考正文表达明确是两项要求：Source和逐字转写继续不可变；在独立编辑层明确给出采纳的理解、依据、核验状态和修订记录。不能因为中文来源有歧义，就让所有最终参考答案永远停在unknown，也不能把编辑选择标成已经核验的官方原文。

本轮用户明确同意：凝视到受影响生物自己下一回合开始时结束；推压使目标远离高斯，至多15尺。二者作为参考英文转载作出的编辑裁定，正文给出明确用法，出处及证据等级另外展示。“乏力”历史术语仍未核实；明确注明这一点，并推荐采用多元宇宙版的“失能”条件，不宣称旧词已被证实等价。

范围仅这三项。纠错正文、编辑决定、来源转写分别存储并建立引用。来源身份、译文权威、Rights不因此升级；两书对象不合并、不自动互相替代。六张其他卡仅随新视图重新组装，原始事实不变。

## 替代方案与取舍

仅逐字转写能保持来源，却让含糊／错误文字直接影响可用性；直接覆盖来源会丢失问题与历史；一律等官方正文才展示明确理解会延后用户反馈。本轮采用独立编辑层，承担可能被后续证据修正的风险，同时使依据与选择可见。正式出版核验要求保持，不把参考裁定当成官方勘误。

## 版本、追溯和反馈

旧六项样本、八卡r2、原评测与首次答卷全部冻结。创建独立r3参考视图；沿用知识对象ID，对变更对象增加Revision，编辑决定使用新ID。原文证据ID与字节不改，新增修订记录说明旧呈现与新呈现。

反馈记录至少应包含具体对象／来源版本、争议条款、当前解释、建议改法与可用证据；引用的证据不得因玩家提交而自动升级。工作流为received → under_review → resolved_by_revision或rejected_with_reason；核验后若确需修订，保留旧决定并追加新Revision与适用范围。只有存在反馈才登记，不伪造玩家报告。不在本轮搭建反馈服务、Runtime、正式Schema、Release或Terminal界面。

AI消费必须区分问法：问“本中文参考采用什么”时给出本轮编辑裁定；问“旧版出版原文是否已核验如此”时仍说明未核验。对“乏力”应能同时表达历史等价unknown与推荐用法为失能。推荐不等于旧词的确定翻译，也不自动改变另一书的来源。

平台层面只涉及通用的来源、编辑决定与修订责任，不把D&D条件或怪物字段提升到Core。最终希望优于原中文资料，具体精度提升仍需逐条证据、反馈和核验验证，不能以目标冒充已经全面更准确。
