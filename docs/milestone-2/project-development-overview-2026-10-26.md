# LoreBuddy从零到完整逻辑模块：项目节奏总览

日期：2026-10-26。用途：给用户查看主线、当前位置和阶段出口。**这是按能力整理的总览与节奏建议，不重编号ROADMAP中的Milestone，也不自动修改当前合同或授权后续生产。**

依据：现行ROADMAP、M2实施合同§19–22、P6用户决定及八对象正式化报告。历史“完成”仅适用于对应交付范围。

## 1. 一条主线

```text
保护原始资料
  → 建成可阅读、可追溯的资料库
  → 明确版本与规则采用范围
  → 建立逻辑模块和规则簇候选表达
  → 用AI/程序验证实际消费
  → 固化通用生产协议                 ← 当前需要收敛
  → 完成首批正式规则与交付闭环         ← 当前另一项重点
  → 用少量未见材料验证生产方法可复用
  → 按选定规则领域与书籍分批扩产
  → 持续交付可读、可查、可解释、可计算的知识包
```

“完整”须限定规则系统、版本、书籍和机制覆盖。近7000个Source Entry不等于近7000条规则；正式知识覆盖与程序执行覆盖分别记录。无需等待全库、所有机制全部自动化之后才交付前面已完成的能力。

## 2. 从过去到未来的阶段清单

| 阶段 | 要解决的问题 | 当前状态 | 走到什么程度就进入下一阶段 |
|---|---|---|---|
| 0 定位与底线 | 做什么平台，哪些来源不能改，版本和身份如何保留 | 已有架构基线 | 有明确产品目标、来源保护和职责边界 |
| 1 资料摄取与可读化 | 将原始容器解包、登记并生成可阅读资料 | M1基线完成：6819份Note及相应Manifest/资产/导出 | 人能够使用资料，文件与来源可核对 |
| 2 来源与版本选择 | 区分书籍、版本、译文与采用环境 | 已有受限输入接纳与候选分类；出版身份/译文/权利并非全部核验 | 当前批次的选定范围明确，未知不被冒充已核验 |
| 3 规则表达试验 | 能力属于谁，法术怎样复用，条件/例外/状态如何关联 | 样本层已有共同结构和多轮试验，尚非全书定型标准 | 能表达真实交叉关系，完整内容与解释层分开 |
| 4 消费路线验证 | AI怎样使用材料，哪些问题交给确定性程序 | 多轮AI试验已形成边界认识；计算器路线已建立 | 对路线有实际样本证据，停止反复寻找通用Prompt最优解 |
| 5 完整候选批次闭环 | 完整规则簇能否被程序读取、绑定、计算或正确拒绝 | 八对象45能力、11法术及共享材料；48题通过，P6已接纳内部候选 | 该批输入、结果、未支持机制及接纳范围清楚 |
| 6 通用生产协议 | 新材料怎样分类、拆分、复用、组簇和登记执行覆盖 | **当前待收敛**；六条原则及外部调查建议尚未全部固化为可执行条款 | 换材料/执行者仍有一致判断；已知类型可配置，新机制有明确入口和停止规则 |
| 7 首批正式化 | 样本怎样成为审核通过、来源保真并可交付的正式知识 | **当前进行中**；70项审核材料已装配，批准0；规范保真链等仍待闭合 | 本批来源/语义/结构/保真通过相应审核，按已批准范围确定性生成首份交付；实际正式格式的消费另验 |
| 8 小批复用验证 | 是否还需要每批临时设计，协议能否处理未见材料 | 未开始新的通用流程复用批次 | 少量新类型材料可按同一流程生产，问题能定位到数据、协议或消费者，而非每次重做架构 |
| 9 按领域有限扩产 | 扩到选定书籍、完整对象和更多机制 | 待前序证据及具体批次确认 | 每批有覆盖清单、依赖、验收和停止点；正式知识覆盖与执行覆盖均可查 |
| 10 形成完整模块体系 | 在明确范围内形成稳定知识、组合与消费能力 | 未来目标 | 常见内容可复用生产，例外明确；更新、迁移、勘误、包依赖和未支持机制均能维护 |

这些阶段会有小范围往返；往返修正某条原则不代表项目退回第0阶段。现行整体治理阶段仍为M2，样本P6完成并不等于M2 Exit。

## 3. 第9阶段怎样展开

按依赖与用户价值分领域推进，而非一次处理全部Entry：

- 通用判定与常用数值机制：骰式、检定、豁免、伤害及调整。
- 条件、效果与生命周期：来源、持续、解除、叠加及恢复。
- 动作、攻击和施法：资格、目标、调用覆盖、选择及资源。
- 生物、物品、职业等内容：复用已有规则和机制，保留各自版本与例外。
- 后续再按明确需要支持更多复杂交互、其他TRPG系统及用户自定义规则。

上述是分组建议，不是已批准的实施顺序。发现新机制时单独扩充机制目录；新增普通对象不应自动带来一个新引擎。每批均可同时产出人类阅读内容、AI可读结构和消费者支持范围内的执行材料。

## 4. 用三条轨道管理，避免所有问题都挤成一个阻塞

| 轨道 | 负责什么 | 节奏 |
|---|---|---|
| 来源与知识生产 | 完整内容、边界、出处、规则采用、保真、审核与知识包 | 按有限批次推进 |
| 机制与计算消费 | 受控操作、参数绑定、算法版本、执行覆盖和停止行为 | 随实际机制需求增长，不要求所有内容都可执行 |
| 产品使用 | 人类展示、检索、AI解释、计算预览和应用交互 | 消费已满足自身门禁的批次，反馈问题；Buddy和Terminal分别承担职责 |

三条轨道各有当前门禁：知识获批不等于自动化完整，计算通过不等于来源获批，产品接入也不替代这两者。正式发布、公开授权和战斗状态写入仍分别治理。

## 5. 现在只盯两个阶段成果

**近期目标A：固定第一版可复用生产协议。** 将现有设计、研究和八对象经验收敛，明确对新材料的处理标准。出口是“能按这份协议做下一批”，而不是预先穷尽整套TRPG所有机制。

**近期目标B：完成首批正式化闭环。** 把八对象作为首批，补规范保真链，完成对应审核及批准，形成明确的正式交付范围。共享整页参考与正式原子规则要区分；不把70个审核对象数当成最终正式节点数。

两项可以在边界稳定的部分交叉推进。它们完成后，再决定阶段8的小批材料，不在目前同时启动全库生产、完整状态引擎、多人同步、云端AI和第二系统建设。

## 6. 建议的节奏控制规则（待采用）

1. 同一时间只维护一个主批次、一个明确的下一出口；研究可以并行，但不自动增加本批必做项。
2. 新发现先分类：影响当前正确性/准入的阻断项、可记录的当前能力边界、后续功能。不能把三类都当“现在必须补”。
3. 当前批次的验收范围只因真实缺口而修订，修订时说明影响，不因看到其他项目某项能力就扩大范围。
4. 每次交付只报告四件事：本批完成什么、还有什么阻断、哪些明确不支持、下一步是否满足启动条件。
5. 不估算没有依据的总体完成百分比或全库工期；按实际阶段出口恢复可控反馈。
