# AI助手可靠性设计方案

日期：2026-10-21。状态：产品约束已按用户本轮意见收敛；以下模块、协议和默认次数为具体设计提案，尚未实施或完成性能验收。本文件不改变M2 Exit Gate，不启动Runtime、Schema、Terminal或全量生产。

## 1. 已确认的产品约束

- 跑团开始前选择规则包，正常问答沿用同一选择，不要求每问重选来源。
- 默认兼容不升模；不把Luna high设为复杂问题必经复核步骤。
- 用户在输入完整性重测中进一步明确：默认不调用6.1或追加高模型兜底；只有用户明确提出时才启动高模型。
- 未来允许用户自带API Key及配置模型。用户若配置更高能力模型，可直接用其处理请求，不强制先经一次较低模型调用。
- 关键事实绑定证据、展示前检查、失败定向重答和明确回答边界作为可靠性方向。
- 不以任意拒答制造高准确率；同时衡量正确率、有效解决率、澄清和等待代价。

后续验收按用户确认的[辅助判定内容口径](assistant-content-acceptance-2026-10-21.md)：规则关系、结论和解释优先，纯status或引用展示错误单列，默认不因此执行完整第二次模型审查。下文检查与修复流程是未来设计提案，不能据此将这些次要问题重新设为默认阻断门槛。

## 2. 开团时生成固定规则环境

开团配置维护所选Package及精确版本、共享规则上下文、采用的编辑参考层及House Rule、声明用途覆盖和玩家可读取范围。系统检查必要依赖、兼容和冲突；不能将“包已安装”当作冲突已解决或所有玩家都有读取权限。

配置通过后形成该团的固定规则环境。后台按此环境选材料，不再每问让用户选书。更高模型也不能越过该范围引用其他版本。

若同名对象的两个版本同时被选择，不能仅靠包集合消除歧义：应在开团配置指定默认变体，或把实际遭遇中的生物实例绑定到具体规则对象。允许多个变体共存，身份不按标题合并。只有仍未绑定的真实歧义才向用户澄清。

已安装包更新不自动改变进行中的团；未来如需变更，由显式配置变更处理，保留旧团的可解析环境。此为未来正式产品的版本约束，不要求当前每次样本修改追加整套快照。

## 3. 七项逻辑职责

这些是职责边界，不是七个新Package或服务。

| 职责 | 维护和输出 | 不承担 |
|---|---|---|
| 规则环境 | 固定包集合、对象变体选择、已确认覆盖及读取范围 | 不因包名宣称出版身份已核验 |
| 事实与证据 | 已审核事实、能力归属、来源范围、法术调用及局部例外、来源特定状态、编辑决定 | 不把运行中的HP、骰果或来源不明主张当作静态规则 |
| 任务材料组装 | 本题对象、用途所需依赖、例外、缺失输入及覆盖说明 | 不静默截掉必要规则，不把参考关系全当强制安装依赖 |
| 答案草稿 | 用所选模型提出结论、事实引用和简短依据，区分确定／有条件／不足 | 不自行创造规则身份、事实参数或来源 |
| 展示前检查 | 引用解析、对象与版本、已支持数值、调用例外、必需依据和输出结构；返回具体错误 | 不宣称能够证明任意自然语言推理正确 |
| 人类呈现 | 根据已通过事实生成关键数值、名称和引用；附简洁解释及未知项 | 不重新自由改写关键字段，不将编辑解释标成原文 |
| 模型适配 | 用户所选服务、模型及调用格式，按配置调用 | 不改变规则环境和检查标准，不默认后台升模 |

事实与证据复用LoreBuddy既有维护边界。规则簇仍是按用途组合事实和依赖；发布包仍是版本、权限、交付边界。问答时生成的任务材料是可重建消费表达，不成为第二套事实源。

## 4. 单次回答流程

1. **定位任务。** 沿固定规则环境定位对象和问题用途；优先使用当前选中的生物、能力或遭遇绑定。自然语言定位失败时提出具体澄清，不以模型自报信心代替判断。
2. **组装材料。** 从该对象展开本题必需的能力、共享规则、法术和例外。保持来源及编辑层区别。必要依赖超出输入预算时拆分任务或报告范围不足，不静默裁切。
3. **生成草稿。** 默认一次模型调用。草稿携带结论、所用事实／证据引用、必要前提、缺失输入、回答类型和简短解释；字段名及正式Schema待后续合同确定。
4. **检查。** 程序检查可判定部分；直接查询的关键数值与名称回读事实记录，引用由已解析证据生成。复合结论检查是否具备所需依据及前提；尚未支持的推理类型保持显式边界，不能因为引用ID存在就视为语义正确。
5. **发布或修复。** 检查通过后呈现。失败时给同一模型聚焦材料及错误类型，默认最多重答一次；仍失败则返回能确认的部分及具体缺口。重答上限是预算提案，不是准确率承诺。
6. **可选的强模型路径。** 用户预先选定更高能力模型时直接用它。一次请求失败后也可由用户主动选择高模型重新处理；不自动升级、不无限互审，不依赖Luna high作为质量门槛。

运行中缺失事实与资料缺失分开：没有提供豁免结果，应询问骰果或给出条件分支；缺少法术依赖，应说明内容覆盖不足；资料中的“乏力”历史对应未核验，应保留未知并呈现明确标注的推荐。它们不能共用一句笼统的“模型不确定”。

## 5. 约束事实，又保留自然阅读

直接参数查询尽量由事实记录确定性呈现，例如旧版触须固定伤害15、能力名支配怪物；模型负责选择相关事实和解释组合关系。关键字段在最终呈现时不再交给模型重新填写。

复杂结论仍可用自然语言，但每个决定性主张应能对应所用条文或编辑依据，避免加入无依据的旁支解释。该方式降低自由生成引入新事实的机会，不能保证所有矛盾和遗漏都能自动发现。需要通过新题及反例检验其收益。

最终回答提供简短结论、决定性条件与可展开来源；技术ID与检查日志不进入正常用户流程。未通过检查的规则断言不先行显示。快速反馈与规则正文分开处理，具体首字策略另行设计。

## 6. 与五个内容重点的对应

| 内容重点 | 必需表达 | 本批例子 |
|---|---|---|
| 能力归属 | 对象、变体、能力的明确绑定；关键参数随能力维护 | 旧触须15不从新卡22继承 |
| 法术调用与例外 | 精确法术身份、同版规则依赖、调用方局部修正及其范围 | 无成分不自动取消专注；引用两项法术和专注规则 |
| 来源特定状态 | 谁施加、以何条件发生、随何事件终止，运行实例由消费者提供 | 不能只凭任意受擒标签推定该怪物采脑前提成立 |
| 用途覆盖 | 本题必需与分支依赖、哪些信息缺失、能支持什么回答 | 读得出法术名不等于已具备判断持续时间的依据 |
| 包依赖 | 安装时版本和兼容闭合；查询时按用途展开对象集合 | 共享规则与怪物／法术维护分开，不要求整个怪物库与整个法术库相互依赖 |

## 7. 自带API Key与不升模兼容

规则事实、任务材料和检查结果使用模型无关表达。支持结构化输出的服务可直接采用；仅支持普通文本的服务可要求返回约定JSON并在本地解析。格式失败同样受重答预算约束，不通过放宽事实检查换兼容。

兼容的含义是相同规则环境、相同检查和失败行为可工作，不代表任意模型具有相同准确率或都能适应输入长度。后续应公布实测的能力边界。模型配置可以改变，团的规则包与解释策略不随之变化；凭据由独立凭据配置维护，不进入内容包和测试答卷。

## 8. 与本版相比的代价及替代方案

- **前置材料成本：** 维护事实引用、调用例外和用途依赖，增加生产与审核工作。复用既有成果，不另起整套事实库；无法在当前样本上给出可信全书工时。
- **前置工程成本：** 编写任务材料组装与有限检查规则。检查器本身也需测漏拦、误拦；本轮R09误报说明不能把检查器当无误权威。
- **每次请求成本：** 正常情况一次生成及程序检查；触发修复最多再一次同模型调用。定位需要模型调用时须另计，不能隐藏在“一次回答”口径中。材料缩减可能省输入，但目前未实测净费用。
- **交互成本：** 少量问题需要澄清；检查失败的问题等待更长；复杂问题可能只获得部分可靠答案。直接解决率必须一起报告。
- **统计限制：** 目前不能承诺99.9%或给出预计提升几个百分点。

不采用所有请求双模型互审：费用普遍增加，同源错误仍可能保留。不采用每问临时选来源：开团环境已承担此职责。不立即实现完整可执行规则引擎：当前范围和证据不支持其成本。保持“固定环境、按用途给材料、约束事实、有限检查与重答”的可验证方案。

## 9. 下一步验证提案

不立即实现未来Runtime。可先以当前样本做离线对照：A本版材料首答；B固定团规则环境＋按用途材料＋事实绑定呈现；C在B上增加检查及最多一次同模型重答。使用未见新题，不读金标准；medium作为不升模主路径，无强制high复核。

测试自然问法、同名对象共存、缺运行输入、依赖缺失、局部例外、长对话对象切换和材料预算不足。分别记录首次正确、最终错误暴露、有效解决率、澄清率、误拦漏拦、调用数及实测费用／时间。把数据错误、材料漏项、模型错误和检查器错误分开。

正式字段、物理封包、实现范围、迁移及准入条件在后续合同中确定；本文件是可讨论设计，不是实施合同或已验证能力。
