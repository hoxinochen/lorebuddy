## 3. 各层维护什么

**怪物模块**拥有卡头防御和各项能力；能力归属明确指向其原型，现场实例另行引用原型，不能把魅魔的防御传给它的目标。

**法术模块**拥有完整法术正文；魅魔无成分、八环施放，梦魔仅免材料、幽魂跨位面可见、绿蟾隐形术仅限自身等调用覆盖仍留在调用方。法术调用关系指向独立法术对象，不复制出另一种同名法术。

**公共规则模块**维护完整共享正文。抗性、取整、免疫、长休、状态及使用次数不在每张卡另造事实。共享法术的完整文本和共享规则整Entry都送达，不能只留一个名称。

**数值表达候选**描述基本顺序及从已选条款取得数值的方式。所有11项具有直接伤害条款的怪物能力均有伤害Facet，含未出题的水体易感与恐惧面容；噩梦另有完整条件分支。火球术、托梦术、以太化和灼热射线的数值段也有独立Facet，不因当前执行器不会使用而删除。

这里没有把原文转换成可任意执行的代码。数值Facet与条件、点燃、诅咒、状态、恢复及整卡替换共同保留；只完成数值不能标记整项能力完成。距离、次数、骰式、数值门槛和结束时点也仍是各自语义，不统一塞成伤害参数。

**规则簇**按五个完整对象组合其内容和直接依赖。魅魔/梦魔互换数据关系同批交付；对象双向引用不推导正式Package循环依赖。当前是本地实验交付目录，不创建正式Package；未来发布的授权、访问控制和依赖锁仍需单独决定。

原文、候选采用与研究回执分开。梦魔Hypnotic截短映射、绿蟾采用卡载DC14/+6而不把译注当官方勘误、魅魔上限恢复的公共长休依赖均保留。没有把当前互联网内容引入构建或重新核验本地出版印次。

## 4. 题目安排

18道范围内数值题包括：汲命之吻成功/失败、实际骰果、取整为零、无抗性、易伤、重复抗性与易伤、免疫；不同对象能力与防御的组合；固定值与骰式加值；火焰灵光/首次进入空间/回合末在物件内的已确认触发；从怪物施法列表找到火球术再读共享法术；混沌法杖的伤害与附带状态分离。

题目询问单次伤害子任务时，卡中仍保留完整能力，包括点燃、诅咒和随机状态；评分要求标注未完成的关联效果，不允许“伤害成功”被表达为“整项能力全部应用”。这是明确任务范围，不是从生产数据中删掉复杂条款。

6道边界题分别是：噩梦按当前HP分支并处理昏迷、临时HP与实际HP变化、多目标灵光及点燃、按来源撤销诅咒、长休整卡替换后的实例数据迁移、缺豁免结果。前三者仍有可以源对照的规则数值，保存在评分侧；当前核心不支持完成整个请求，不能用局部数值冒充全答。

“18题范围内”只表示**若能正确读取并绑定事实，其数值机制在现有核心范围内**，不是预先认定现有产品已会读取本格式。全部24题都要测试读取入口，边界题也不能不读材料就套用统一拒答。

## 5. 消费交接与禁止绕过

执行侧只获得`input/`，不读`evaluator/`、`produce.py`的Gold构造段、结果模板或旧LLM答卷；保存输出之后才开启评分。目录分离不是操作系统沙箱，应核查实际传入和读取日志。

标准路径是：读取共同语料 → 按现场原型身份与宣告能力定位拥有者 → 解析法术/公共规则引用及调用覆盖 → 从固定值或已记录骰果取得原始伤害 → 合并目标固有防御和已确认现场效果 → 判断所求任务是否受支持 → 调用现有核心或明确停止。

上述是通用消费职责，不是24道题的标准参数答案。允许未来由通用读取器确定性完成绑定，但本轮不实现它，也不允许以手工逐题填入旧核心Envelope冒充读取成功。已有入口若只接受request/context，应报告`data_ingestion_not_implemented`，数值端到端测试Not Run；可以另行说明底层运算理论上支持，不重复上一批手工输入的成绩来替代本轮结果。

不能将源码现场补丁、新增适配器或让LLM代读后的结果当作“现有计算器原样通过”。若另行获准实现读取器，须记录实现变化，并把它与原有能力结果分开。

## 6. 评分与时间

逐题至少保存：完整语料是否读取、正确对象及能力绑定、实际规则依赖、所取现场事实、计算阶段和结果、尚未执行的效果，以及完整请求是否完成。所有阶段以实际输出为准，不由评分脚本代补推理过程。

分别报告：

1. 24题的数据读取与绑定覆盖；未实现/未运行单列。
2. 18题的数值子任务严格正确率和端到端完成率；不能只在少数读通题中筛选后报100%。
3. 6题的边界/缺输入处理；必须有与题目匹配的原因，不能因为入口完全不读材料就记6/6边界正确。
4. 关联效果覆盖；伤害成功不等于点燃、诅咒、状态或HP写入已支持。

计时分别记共同语料加载、每题定位绑定、核心计算和总响应；共同加载成本既报告一次值，也注明是否复用。首次加载与预热分开；缺读取器时不得捏造0毫秒读取。保留运行环境和题目范围，不拿本次全链路时间与上批纯核心时间直接计算提速倍数。

本批是新题，不能直接继承旧LLM同题正确率，也没有新模型耗时。本轮不调用Luna或6.1。
