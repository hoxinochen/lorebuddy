# 本地伤害计算器研究稿

日期：2026-10-22。状态：研究设计与预期案例，未实现、未验收。用户已同意“通用组件按许可复用、小型结算核心自行实现、内容授权分离”，本轮授权开始研究。本文不启动AI Runtime、Terminal修改、平台Schema实施或公开发布。

后续状态：用户已指定在本会话继续开发，现已完成[隔离样机](local-damage-calculator-prototype-2026-10-22.md)。下文保留样机前研究口径；当前实现与Not Run项以该报告为准，不回写原预期或历史模型成绩。

## 1. 要解决的具体问题

[六卡批次](cross-relations-6cards-report-2026-10-22.md)D09中，模型收到完整材料仍漏用成功半伤：原始13、豁免成功、心灵抗性，应经历13→6→3；模型答6，且连带上限减损也错。该题不是Source错误。计算器应从选定能力读取分支，并在缺少豁免结果时停下来，避免让AI自行选择哪些步骤存在。

本轮交付为本研究稿与[机器可读预期案例](local-damage-calculator-cases-2026-10-22.json)：34项运算/拒算、12项比较/分流，共46项。案例是未来实现的验收输入和Gold，不是已执行测试，不能报告“计算器通过率”。未新增候选卡，未运行模型，未安装依赖或复制第三方代码。

## 2. 推荐范围和明确代价

首个研究样机只支持一个已选规则环境、一次伤害事件、一个目标、一个伤害类型。给定非负整数的豁免前伤害，处理能力规定的成功半伤/成功无伤/无豁免、伤害抗性、易伤、免疫、逐阶段取整，以及明确规定“等于受到伤害”的减损数额。只返回提议结果，不扣血、不施加状态，不计算新HP上限或死亡。

规则Profile先限定为D&D 2024 / SRD5.2.1。其规则顺序和damage_type词汇是系统扩展，不提升为平台Core。通用算术与Profile分离是本次局部设计建议，不宣称已经证明跨系统语义一致。

暂不支持：掷骰/骰式解析、攻击是否命中、DC和优势判定、条件是否实际满足、2014 Profile、混合伤害、多个伤害事件、其他固定减伤/加伤、反应减伤、穿透抗性、附带状态、临时HP、长休恢复和伤害触发事件。第一版遇到这些情况返回明确未支持，不偷偷按普通伤害处理。

限制混合伤害的原因是必须先确认同一事件的分组和取整单位；拆成两个奇数分量分别取整可能改变结果。范围缩小会降低可直接回答的问题比例，应同时报告未支持率，不能用拒算制造高正确率。后续按新机制增加支持，不因增加怪物数量增加专属计算分支。

## 3. 事实归属与双向计算

| 责任 | 维护者 | 计算器不得自行补造 |
|---|---|---|
| 能力身份、伤害类型、豁免分支、关联减损 | LoreBuddy候选/未来审核事实 | 不从同名能力或别版补齐 |
| 规则顺序与取整 | 系统专属Profile，绑定来源及审核状态 | 不由AI发送任意执行顺序 |
| 目标固定防御 | 选定目标卡的事实记录 | 不把攻击者防御搬到目标 |
| 运行中额外防御、骰果和实际豁免结果 | 用户/未来消费者提供的现场事实 | 不把缺少字段当“没有抗性”或“豁免失败” |
| AI的计算草案与解释 | AI | 不作为工具规则来源或计算参数 |
| 运算和差异检测 | 本地确定性代码 | 不宣称能证明整段自然语言正确 |

建议流程：AI先固定草案及可公开的简短计算阶段；本地工具接收能力ID和现场事实，从预加载对象及Profile解析规则；程序比较结果与关键阶段。一致只能标记“本次计算一致”，不能标记“答案已验证”。AI不需要输出私有思维过程。

两路并非统计独立：它们可能共享错误的能力选择或豁免结果。需要一个由用户/消费者固定的任务上下文，至少包含规则环境、能力、目标和现场输入；比较必须同时检查这些身份与值。若上下文也是AI独立编造，双方仍可能一致地错，必须把该残余风险记录出来。

工具看到的是调用请求，无法察觉用户原话中被AI完全隐去的额外效果。预加载能力的必需字段校验可以拦下遗漏豁免；“现场防御完整”“无其他修正”等声明只能表示本题范围已被提供方确认，不能把AI填写true当作内容已经核验。

## 4. 拟议接口

以下是研究用表达，不新增正式Schema或通用version字段。

### 输入

```text
request_id
environment_ref                 预加载并锁定的规则环境
ability_ref                     稳定ID及候选修订；由工具解析分支
target_ref                      目标实例/卡的绑定，不能仅靠名称
event_ref                       当前伤害事件，避免比较另一轮结果
facts:
  raw_damage                    非负整数；建议研究上限1,000,000，属于工具限制
  damage_basis                  必须为before_save_and_defenses
  save_outcome                  success / failure / not_applicable
  eligibility                   confirmed / unknown / rejected
  target_defenses_ref            预加载目标防御快照
  extra_defenses                 明确的现场额外防御及来源
  defense_coverage               confirmed / unknown
  other_adjustments             明确为none；有其他操作则首版未支持
```

工具不接受AI覆盖ability_ref对应的success分支、damage_type、取整规则或关联减损。可变现场数据应与固定事实分开。输入格式可以做严格白名单；未知字段不能静默忽略，否则传入穿透抗性等效果也可能得到看似成功的错误答案。已知但未支持的字段与任意未知字段分开报告；多项问题同时存在时先返回问题清单，不能靠免疫等提前返回0绕过必需输入校验。实际字段和错误码在样机阶段再固定。

### 输出

```text
request_id, environment_ref, ability_ref, target_ref, event_ref
status                           calculated / needs_input / unsupported / invalid
missing_fields[] / issues[]      失败时不给默认0或伪造最终数值
resolved_facts                   工具实际使用的分支、类型、防御及来源
stages[]                         before、operation、after、rule_ref
damage_taken                     此事件结算伤害；不命名为hp_lost
linked_reduction                 仅返回已支持能力的关联数额，不更改实例
coverage                         明确包含和排除的范围
```

同一输入及预加载定义应生成相同结果。日志时间放在执行外层，不能让当前时间改变规则运算。核心应是无副作用的函数，传入对象保持不变。

### D09在接口中的解释

能力的成功分支来自既有SU.ABILITY.5，现场输入只提供原始13、成功、防御中有心灵抗性及资格已满足。工具解析半伤→抗性，返回6、3两个阶段，damage_taken=3、linked_reduction=3。AI草案6/6产生明确分歧。长休恢复不在本计算范围，不能因数值部分通过就声称整道原题已验证。

## 5. 计算规则与来源核查

本轮直接核对[官方SRD5.2.1](https://media.dndbeyond.com/compendium-images/srd/5.2/SRD_CC_v5.2.1.pdf)：印刷页16–17为成功半伤、抗性、易伤及顺序；页187为默认取整；页331为汲命之吻关联减损。研究性归纳为：先能力分支及已支持修正，再抗性，再易伤；同类防御不重复应用，免疫对应伤害为0。逐步取整，不能先抵消抗性和易伤；13遇两者得到12。此为摘要与计算采用建议，不是逐字转写或正式Rule Assertion。

免疫的无伤数值不授权任何额外触发推理；样机不能据此判断某些特殊附加效果是否触发。临时HP及HP上限钳制不进入计算，避免把damage_taken等同于hp_lost。未来扩展必须先定义两者及事件边界。

本地D09的来源链仍沿既有六卡工件：能力证据ID `urn:uuid:46a2542c-6f20-5f68-a067-ae2ca9c62e96`，抗性通则 `urn:uuid:402203e6-571b-54e7-a3d8-505244256f62`，取整 `urn:uuid:8d9ed635-0e59-547b-afd7-0a10224ca485`，见[既有证据](../../build/m2-cross-relations-6cards-2026-10-22/evidence.json)。它们仍为受限候选，出版claimed、译文权威/权利unknown。本次网页核对是研究参考，不冒充已摄取Source Fragment或已审核节点。

## 6. 比较、分流和高级模型

| 条件 | 建议行为 | 理由 |
|---|---|---|
| 输入齐全，结果和必需阶段一致 | 呈现工具数值及简短解释 | 只表示支持范围内一致 |
| 数值一致，关键阶段缺失/冲突 | 标记stage_mismatch，进入争议处理 | 不能因碰巧同分就漏过步骤错误 |
| 数值或关联减损不一致 | 标记numeric_mismatch，进入争议处理 | D09应在此被捕获 |
| 缺豁免、资格或目标防御覆盖 | 请求具体现场输入 | 高模型不能创造事实 |
| Profile/能力/目标/事件不匹配 | 拒绝本次比较，重新定位 | 不能比较另一对象的相同数字 |
| 未支持的效果 | 返回范围不足 | 允许后续模型解释，但不能声称通过计算器 |
| 两路共享错误现场输入且一致 | 不保证检测；保留人工/来源核验 | 双向计算的已知漏检边界 |

用户已同意“冲突时自动请求高级模型”的设计方向。建议未来每请求最多一次高模型核查争议来源、规则适用及现场输入，再用相同本地核心重算。高模型不能通过更改Gold、工具代码或数学顺序来强行消除冲突；重算仍失败就显示分歧。模型选择与费用权限由未来配置提供；未配置则显示冲突，不强制联网。本轮没有实际调用高级模型，也没有推翻“默认不跑6.1”的测试约定。

比较是本地函数，不再消耗一轮模型调用；但AI自行草算会增加输出，真实调用中工具往返也可能增加模型轮次。普通function calling下若草案、调用同次生成，工具返回后仍可能需要模型续答；可以由页面直接呈现已验证数值减少这一轮，但完整自然语言整合尚待验证。不能承诺“正常一定只有一次API调用”。

第一次AI草案在计算器结果送回前固定，修订不覆盖原草案。最终数值由本地结果直接渲染，或在AI续答后再次核对，避免解释阶段把3写回6。快速首字、流式UI和真实API成本不在本研究验收内。

独立实现不解决内容授权。研究材料仍保留在受限项目中，不将现有CHM中文卡作为商业默认数据。未来可分发的规则Profile需独立核查SRD覆盖、CC BY 4.0署名与修改声明；软件许可证不替代内容权利。商业交付前核查最终文件及依赖，不把本研究当法律无风险保证。

## 8. 本地交付、版本与迁移

建议独立维护纯JavaScript核心、D&D专属Profile和样机页面，构建时把必要代码和数据内联到一个HTML。核心不依赖网络、DOM、Node专属模块、eval或任意用户公式执行。无需服务端或MCP进程，未来AI适配器只转交结构化请求。文件离线打开不依赖fetch；这仍是设计要求，未完成浏览器实测。

应用代码修订、接口修订、规则Profile修订与能力记录修订分别表达，未来由预加载环境固定；不把一个泛称version用于全部。缓存只存派生结果，不能取代能力事实和来源。变更规则顺序需新Profile修订和回归；原候选不回写。现阶段不新建正式Package或Core字段；未来正式化时仍履行来源、审核、Rights及发布门禁。

大小和速度现在未测，不能给出KB或毫秒承诺。首版接受条件为单文件离线运行、正常/拒算案例符合预期、零网络请求、核心不改变输入、相同输入输出一致；实际体积和浏览器执行时间在样机报告中测量，不能把计算时间当AI总互动时间。

## 9. 下一步样机的验收计划与停止点

先用伴随JSON固定预期，再做小核心和本地页面，最后验证浏览器行为。所有测试预期独立于实现维护，不从计算器输出反向生成Gold。包括D09故障复现、取整临界、重复防御、身份错配、缺现场输入、未支持机制，以及“两路同错”的明确反例。故意漏半伤、重复抗性、抵消抗性易伤、漏关联减损四种错误实现应被案例抓住。

后续样机完成后，另选未见问题做真实AI调用实验，统计正确首答、分歧捕获、误拦、同错漏检、澄清/未支持率、升级数、最终正确和耗时/tokens。当前不运行这轮实验，不用手工构造草案替代真实模型测试，也不因当前案例分数修改历史26/27。

本轮研究停止于规格、证据、预期案例和后续验收范围。尚无可运行计算器、浏览器性能数据、实际自动升模或AI接入。下一步可直接据此制作隔离样机；不自动建设完整战斗Runtime、扩大卡片生产、修改Terminal或发布。
