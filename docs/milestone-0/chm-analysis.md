# CHM 结构分析

状态：只读分析完成

分析日期：2026-07-20

## 1. 分析目的与边界

本分析用于回答：

- CHM 实际包含什么；
- 目录结构是否可以直接代表出版物与知识边界；
- Source 保存和转换需要处理哪些格式风险；
- 哪些事实会约束知识包（Knowledge Package）架构。

本次没有执行 HTML 脚本，没有修改原始文件，没有把解包内容写入仓库，也没有生成任何 Markdown 知识节点。

## 2. 取证方法

1. 读取文件元数据、摘要和 ITSF Header。
2. 使用官方 7-Zip `26.02` 在临时目录只读列举并展开容器。
3. 统计文件、扩展名、目录、编码声明和严格解码结果。
4. 解析 HHC 目录与 HHK 关键词索引。
5. 在不执行 JavaScript 的前提下恢复解析 HTML，统计结构与链接。
6. 对重复文件名、逐字节重复和可见文本重复生成候选统计。
7. 验证本地图片格式和可读取性。

统计结果是当前输入摘要下的事实。输入文件变化后必须重新分析。

### 2.1 可复现性状态

本报告属于有输入摘要和交叉统计支撑的 Milestone 0 取证分析，但还不是符合未来摄取规范的可重放分析回执（Analysis Receipt）。本次使用的临时分析脚本、每个 Parser 的精确版本与全部配置尚未作为仓库规范输入固化，因此不能仅凭本文逐字节复现全部统计结果。

正式摄取必须在对应 Artifact 的 `sources/artifacts/<artifact-key>/receipts/analysis.json` 保存机器可读 Analysis Receipt，至少锁定：

- Artifact 摘要；
- 操作系统无关的工具名称、版本与二进制摘要；
- Parser、Decoder、Recover 配置和统计规则版本；
- 执行脚本或构建产物摘要；
- 输入参数、确定性排序规则与结果文件摘要；
- 每项聚合数字对应的明细文件或可重算查询。

这样设计的原因是：本文适合人审与架构决策，但十年后的审计需要机器能够证明“数字如何得出”。替代方案是只保存命令日志；它无法锁定脚本内容和解析器行为，因此不采用。

## 5. 导航结构

### 5.1 HHC 内容目录

`DND五版不全书.hhc` 包含：

- `8,187` 个 sitemap 导航对象；
- `7,716` 个带非空 `Local` 目标的对象；
- `6,813` 个不同的非空目标；
- `471` 个纯分类或分组对象；
- 最大导航深度为 `7` 层；
- `864` 个目标在目录中出现多次，共形成 `903` 个额外引用。

目录覆盖 `6,813 / 6,817` 个 HTML 页面。所有非空 HHC 目标都能解析到实际文件；未覆盖的 4 页均位于 `空白页模板/`。

HHC 同时承担：

因此 HHC 是重要的来源导航证据，但不是知识节点边界，也不是唯一出版物目录。

## 6. 编码

对 `6,817` 个 HTML 页面加 HHC、HHK，共 `6,819` 个文本条目进行检查：

| 声明情况 | 数量 |
|---|---:|
| 声明 `gb2312` | 6,787 |
| 声明 `gbk` | 1 |
| 无 charset 声明 | 31 |

关键结果：

- 所有 `6,819` 个条目都可以按严格 `GBK` 解码，也兼容 GB18030；
- 只有 2 个条目也能按严格 UTF-8 解码；
- `442` 个声明 `gb2312` 的条目包含严格 GB2312 无法表示的字节；
- 严格 GB2312 解码失败共 `443` 个，其中 `442` 个声明 `gb2312`，另 `1` 个没有 Charset 声明；
- `#SYSTEM` 中的中文元数据同样需要 GBK/GB18030 语义读取。

结论：

1. Source 必须保留原始字节和原声明。
2. 每个 Entry 必须分别记录 `declared_charset` 与 `decoded_charset`；当前样本的实际解码值应记录为 `gbk`。
3. Library 可以转为 UTF-8，但必须记录转换器版本和文本指纹。
4. 不得把 HTML 声明当作实际可解码性的充分证据。

## 7. HTML 结构质量

所有页面都能被恢复型 HTML Parser 建树，但这不等同于符合现代 HTML 规范。

| 结构特征 | 涉及页面数 |
|---|---:|
| 含 `<style>` | 5,243 |
| 含内联 `style=` | 3,957 |
| 没有任何 `h1`～`h6` | 3,610 |
| 含 `<table>` | 2,250 |
| 含 Microsoft Office/WPS 痕迹 | 1,492 |
| 含 `<img>` | 276 |
| 含 `<script>` | 124 |
| 缺少非空 `<title>` | 195 |

“Microsoft Office/WPS 痕迹”按页面源码出现 `mso-`、Microsoft Office URN、`<o:` 或 WPS / `ksohtml` 标记统计。它是页面族候选信号，不表示页面一定由某个单一 Office 版本生成。

高频遗留标签包括 `font`、`span`、`o:p`、大量嵌套 `table`。页面来源包含 WinCHM、Microsoft Word、MSHTML 和 DHTML Editing Control 等不同模板。

根级 CSS 还把部分展示标签当作弱语义约定，例如 `<u>` 表示术语、不同的 `<u>/<em>/<b>` 组合表示法术、魔法物品或怪物，`h4`～`h6` 被部分模板用于条目类别。这些只能作为候选信号；来源模板并不统一，不能直接升级为 Node Kind 或 Schema 字段。

影响：

- 不能用单一 CSS Selector 提取所有正文；
- 不能把每个 Heading 自动视为知识节点；
- 复杂表格、Office 标记和脚注需要保真回退；
- Script 必须禁用并分类，不能把执行后的 DOM 当作唯一来源；
- 模板清理规则必须按经审核的页面族生效，未知模板默认保留并报告。

### 8.2 图片引用

- `369` 个本地引用；
- `170` 个带协议引用；

外部资源不能在转换时静默下载。若未来决定采集，必须作为新的 Artifact 保存原始 URL、获取时间、响应摘要、内容摘要、授权状态和失败记录。

## 9. 重复与冲突信号

### 9.1 名称重复

- `695` 种 HTML basename 重复；
- 涉及 `1,881` 个页面；
- 例如 `魔法物品.htm` 出现 32 次，`前言.htm` 出现 29 次；
- `822` 种 HTML `<title>` 在多个页面重复，另有 195 页缺少非空标题。

文件名、标题和 Alias 均不能作为唯一 ID。

### 9.2 内容重复

- 发现 `15` 组逐字节完全相同的 HTML，每组 2 个文件；
- 发现 `16` 组按本次候选归一化规则得到相同文本的页面，每组 2 个文件；
- 其中多数组来自旧模组与合集中的重复生物条目。

本次“可见文本重复”候选采用固定步骤：按严格 GBK 解码；使用 `lxml` 恢复模式建树；移除 `script` 与 `style` 节点；按 DOM 顺序连接 `itertext()`；把所有连续空白折叠为一个 ASCII Space；对所得 UTF-8 字符串计算摘要。该规则不求值 CSS，因此不会过滤 `display:none` 等隐藏文本；“可见文本”在这里是候选算法名称，不是浏览器渲染等价性声明。正式摄取必须在 Analysis Receipt 中锁定 `lxml` 版本和规则版本。

重复检测只能提出候选。相同文本可能拥有不同来源、版本、适用范围或导航语义，不能自动合并或覆盖。

## 10. 来源性质

首页内容表明该 CHM 是社区维护的聚合项目，并明确提示：

- 官方原文与勘误优先于社区整理；
- 翻译可能存在问题；
- 旧版内容以 Legacy 方式继续保留；
- 不同扩展可能含重复或被新版替换的内容；
- 图片并未完整收录。

所以需要区分：

1. **实际证据**：某段字节存在于这个 CHM 的某个 Entry。
2. **来源声明**：该段文字声称来自某书、某章或某在线页面。
3. **权威判断**：该文本是否为官方原文、官方译本、授权译本或社区翻译。

只有第 1 项可以由当前 CHM 直接证明。第 2、3 项必须通过来源审核和外部证据建立。

## 11. 对知识包设计的直接约束

1. 当前 CHM 必须建模为聚合型 Artifact，不能建模为单一 Edition。
2. Source 必须同时保留原始 CHM、原始 Entry 字节、路径映射与 Inventory。
3. HHC 必须保存为来源导航，并与未来语义导航分离。
4. Entry 编码必须逐项记录；Library 统一 UTF-8 只是派生表示。
5. 节点边界必须结合导航、Heading、Anchor、结构模式和人工审核。
6. 版本、语言、来源权威和适用范围必须成为显式元数据。
7. Alias 索引必须一对多并带语言、系统和版本上下文。
8. 外部图片和坏链接必须进入问题清单，不能静默补齐。
9. Office 附属 XML/THMX 是否无用必须由引用图证明，不能按扩展名删除。
10. CHM 本身无法满足“来源书籍、章节、页码均已验证”的要求；正式发布前必须完成来源分类账本。

## 12. 未解决问题

- 每个顶层区域实际对应哪些 Work 与 Edition；
- 中文文本的翻译身份和授权状态；
- 哪些在线资料是正式发布、Playtest、Legacy 或社区内容；
- 外部图片是否需要、允许且能够长期保存；
- 124 个脚本页面中是否存在只能由 Script 生成的正文；
- 原始书籍页码能否从其他证据补齐；
- 当前 CHM 是否允许以何种方式再分发。

这些问题不会阻止保存 Artifact，但会阻止把未审核内容标记为官方、公开或可再分发。
